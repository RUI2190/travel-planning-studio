# Travel Planning Studio

一个把旅行研究、行程设计、地点数据、手机地图、PDF 指南和发布验收串成完整工作流的公共项目。

这个仓库包含两部分：

1. **可复用的 Travel Planning Studio Skill**：帮助 Codex 为不同旅行者、目的地和时间窗口制作定制化旅行方案。
2. **绩溪·徽州慢旅行公共地图**：展示如何把目的地资料整理成适合手机现场使用的交互地图，而不公开任何个人行程或预订信息。

## 在线示例

[打开绩溪·徽州慢旅行地图](https://rui2190.github.io/travel-planning-studio/)

地图支持：

- 按酒店、交通、景点、餐饮、咖啡、逛店等类别筛选；
- 按地点名称、区域、类别、地址和简介搜索；
- 复制地点名称或公开地址；
- 跳转高德地图和 Apple 地图；
- 选择多个地点并按步行、骑车、开车或公交方式规划路线；
- 在中国大陆网络环境下优先使用可访问底图，并在加载失败时切换备用底图。

地图中的营业时间、票价、交通班次和活动安排可能变化，实际出行前仍应查看官方公告或向经营方确认。

## 这个项目能解决什么问题

普通旅行计划经常散落在聊天记录、收藏夹、PDF 和地图标记中，更新时容易互相矛盾。Travel Planning Studio 提供一套可复用的方法：

```text
旅行需求
  ↓
证据与来源核对
  ↓
统一地点数据与决策记录
  ↓
私人行程 / 公共地图 / PDF 指南
  ↓
移动端、路线、导航与发布验收
```

它特别适合需要同时产出以下两种内容的旅行项目：

- **私人旅行方案**：可以包含日期、同行人、预订、预算、交通衔接和每天安排；
- **公共目的地指南**：只保留任何旅行者都能使用的地点、开放、看点、交通和导航信息。

两种内容共享事实来源，但公共版本不会直接发布私人规划数据。

## 使用 Skill

Skill 位于 [`skills/travel-planning-studio`](skills/travel-planning-studio/)。将该目录安装到 Codex 的 Skills 目录后，可以用自然语言或 `$travel-planning-studio` 调用。

示例：

```text
使用 $travel-planning-studio，为四天的泉州旅行制作一份有来源依据的行程、手机地图和 PDF 指南。私人版本保留我的交通与酒店信息，公开地图只保留通用地点资料。
```

Skill 会根据任务规模选择快速行程、完整旅行包或刷新审计模式，并在需要公开发布时执行隐私分层和发布前检查。

## 隐私原则

公共构建采用字段白名单，而不是把私人内容放进网页后再隐藏。公开地图不会包含：

- 旅行者姓名、同行关系或人数；
- 个人到达和离开时间；
- 酒店入住日期、住宿晚数或“已预订”状态；
- 会合安排、私人备用方案或个人体力偏好；
- 订单号、私人联系方式、支付信息或精确私人位置；
- 只对某一次行程有意义的天气、穿衣和当天执行提醒。

公开版本主要回答四个问题：**这里是什么、为什么值得去、如何到达、哪些信息需要重新确认。**

## 内容与服务说明

- 地图是旅行研究示例，不代替景区、交通运营方或商家的实时公告。
- 小店、住宿和乡村点位若没有公开精确坐标，会以公开地址附近位置表示。
- 高德地图、Apple 地图、OpenStreetMap、Valhalla 和其他第三方服务分别受其自身条款与可用性约束。
- 仓库公开不代表第三方地点资料、商标或地图数据的权利发生转移。
